 FORMAT NOTES:
  Type codes in decoded .cdf files:
    t=0 = byte (uint8)
    t=1 = decimal (uint32 LE, stored as integer)
    t=2 = float (float32 LE)
    t=4 = compound / tuple (multiple values: floats, bytes, or integers)
    t=6 = special (1-byte value, same size as byte; used for tire compound counts, gear count etc.)
    t=8 = null/flag (field absent from binary; value placeholder only)

  CDF Binary Field Layout — Verified across 501 files, 303,814 fields
  =====================================================================

  [marker][hash_b0][hash_b1][hash_b2][hash_b3][suffix...][data...]

  Marker  Layout                                    Meaning                 Verified
  ------  ----------------------------------------  ----------------------  --------
  0x20    BB BB BB BB  DD                            1 byte value             54,908
  0x21    BB BB BB BB  DD DD DD DD                   uint32 LE                14,754
  0x22    BB BB BB BB  DD DD DD DD                   float32 LE               98,221
  0x26    BB BB BB BB  DD                            1 byte (special*)         3,324
  0x28    BB BB BB BB                                no data (null/absent)    30,392
  0xE0    BB BB BB BB                                no data (section)         6,678
  0x24    BB BB BB BB  SS [SS] DD DD DD...           compound (suffix-defined) 95,537

  * 0x26 is 1 byte NOT 4. Same size as 0x20. Semantic use: tire counts, gear count.

    CAUTION: 53 00 and 13 00 are context-dependent (multiple sizes observed).
    Table covers 86% of compound fields. Remaining 14% use rare/exotic suffixes.

  File headers: 24 bytes (91%), 20 bytes (6%), 8 bytes (3%). Skip to first marker.

  Hash ID encoding: decoded [DD CC BB AA] (0xaabbccdd) → binary bytes [DD CC BB AA] (0xaabbccdd) (little-endian) ordering.

  Compound (tuple) format: (default_value, step_size, num_settings)
    Used for all setupable garage parameters. step_size × num_settings = total range.
    E.g. SpringRange=(220000, 1000, 40) → 40 steps of 1000 N/m from 220000.
  Some compounds are pure data tuples (not setup ranges), e.g. Inertia=(Ix,Iy,Iz).

STRUCTURE:
  File sections: [GENERAL] [FRONTWING] [REARWING] [BODYAERO] [DIFFUSER]
                 [SUSPENSION] [CONTROLS] [ENGINE] [DRIVELINE] [DAMAGE]
                 [FRONTLEFT] [FRONTRIGHT] [REARLEFT] [REARRIGHT]
  Some vehicles have additional sections: [REARWING2] [[BE 70 BE 88] (0x88be70be)]=FW2 etc.
  Per-corner sections share the same field IDs (same hash in all four corners).

UNKNOWN FIELD NAMING CONVENTION:
  Fields dfbin_to_df.py could not name are listed as h_XXXXXXXX where XXXXXXXX
  is the 8-digit LE hex representation of the field's 32-bit hash ID.
  Unknown fields are grouped by inferred purpose where patterns are clear.
  Fields marked [ALL FILES] appear in every one of the 404 decoded base-game CDFs.
